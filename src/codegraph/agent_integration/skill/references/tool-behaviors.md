# Codegraph: Known Tool Behaviors (empirically verified)

These are gotchas confirmed by direct use. Honor them to avoid empty results
or misleading counts. See `references/golden-rules.md` for the actionable
rules these behaviors motivate.

| Tool | Behavior | Workaround |
|------|----------|------------|
| `ask_compass` | Routes correctly but returns empty body skeletons when wiki/compass coverage is thin (e.g., 1 wiki, 2 compass files). | Don't treat an empty router response as "no info exists" -- drill down with the specific layer tool. (Phase 1: router now degrades to graph + memory fallback automatically.) |
| `recall_memory` | Substring search across title + description + body + tags. Finds the query only if the exact words appear somewhere in the memory. | For concept-level queries, try broader search terms or put synonyms in memory titles/bodies. (Phase 1: now includes multi-token lexical matching before semantic fallback.) |
| `impact_analysis` | Within-repo ONLY by default. Also: default precise mode only follows resolved edges, so common names report small impact -- until they don't (see next row). | Use `cross_repo_deps(repo)` for cross-repo blast radius. Use `fuzzy=True` when precise impact looks suspiciously small for a widely-used symbol. (Phase 1: output now includes cross-repo consumer reach automatically.) |
| `impact_analysis` on common/lifecycle names | Traversal fans out through name collisions (`onCreate`, `onViewCreated`, `render`, etc.) into hundreds or thousands of unrelated symbols. The response is large enough to trigger a client-side "large MCP response" warning, and the raw count does not reflect real coupling. | Use `scripts/impact_guard.py <symbol>` instead of calling the tool blind -- it detects the collision (via the `cycles` field) and reports it instead of the inflated total. See Golden Rule 6. |
| `search_symbols` | ~~Breaks on underscored tokens.~~ Fixed (Phase 1c): FTS5 handles `*core_ui_v4*` correctly via phrase splitting. ~~Also broke on camelCase substrings.~~ Fixed (Phase 1d): FTS5's `*` only ever matches from the *start* of an indexed token (unicode61 doesn't split camelCase), so `*UseCase*` -- and even a bare, wildcard-free `UseCase` -- previously matched only names literally starting with "UseCase", missing e.g. `UpdateProfileUseCase` entirely. `search_symbols` now unions in a LIKE-based substring pass whenever the pattern isn't a pure trailing-prefix pattern. | Wildcards and substring queries both work now, on underscored and camelCase names alike. Short patterns (`*v4*`) are still fine for broad matches. |
| `get_callers`/`impact_analysis` on a Kotlin class invoked via `operator fun invoke` | ~~Returned 0/empty for every class only ever called as `someUseCase(params)`~~ (DI-injected property, `.invoke()` sugar -- the standard Android UseCase idiom). Fixed (Phase 1e): the edge previously resolved to the *local property* declared in the calling file (a real but useless resolution via the same-file tier), never the invoked class, no matter how many call sites existed. The parser now rewrites these bare-call edges to target the callee's declared type. | None needed -- fixed. `this.someUseCase(params)` (an explicit receiver) is a narrower remaining gap; cross-check with `fuzzy=True` or a grep if a result there still looks emptier than expected. |
| `semantic_search` | Defaults to RRF fusion (BM25 + vector, `CODEGRAPH_FUSION=1` default): the returned `score` is a rank-fusion number (~0.01-0.02), not cosine similarity, regardless of the `threshold` argument. Real cosine scores (0.3-0.6+ for genuinely on-topic hits with `local`/`BAAI/bge-m3`) only show when fusion is off. | Rank order is meaningful either way. Set `CODEGRAPH_FUSION=0` if you need the score to reflect actual match strength (e.g. deciding how confident a hit is), not just relative order. |
| `get_callers`/`get_callees` fuzzy | Common method names (`install`, `trackedClick`, `getScreenName`, etc.) fuzzy-match unrelated symbols across other repos/languages that merely share the name. | Verify a fuzzy hit's file path/package matches your domain before treating it as a real caller. Fuzzy candidate count is not evidence of real usage. |
| `trace_flow` | Read-only downward call-chain trace. Returns "No outgoing calls" when the entry has no *resolved* callees — not when the symbol is missing (verify with `find_definition` first). Large flows (e.g. `handleCommand`) can return 300+ steps. | Use to scope a flow before `generate_flow`; cap with `max_depth`. Branches and terminals come from the L1 graph, no compass coverage needed. |
| `generate_flow` | Write tool (critic-gated): writes `compass/flow-{entry}` only if the critic passes; on rejection returns the error list and writes nothing. With `as_workflow=True` the workflow doc is written regardless (tier=asserted, not critic-gated). | If critic rejects, it usually means a stale graph — run `cg build` and retry. The workflow (if requested) still ships on compass rejection. |
