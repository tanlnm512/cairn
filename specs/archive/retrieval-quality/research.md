# research.md — external grounding for retrieval-quality (RQ1–RQ5)

**Author**: researcher (Stage 1) · **Date**: 2026-08-16 · **Method**: web search + arXiv/paper abstraction, breadth-first, narrowed to sources that actually answer each RQ.

## RQ1 — Query-document mismatch without an LLM

- **source**: [Hui et al., A Comparative Study of Pseudo Relevance Feedback](https://khui.github.io/files/publications/Hui2011_Chapter_AComparativeStudyOfPseudoRelev.pdf) · **claim**: RM3, Bo1, Bo2 and divergence-based PRF all reliably improve retrieval by reweighting/expanding from top-ranked docs, with effectiveness sensitive to feedback-doc count and original-query weight. · **relevance**: RQ1/FR-001 · **confidence**: high
- **source**: [Otero 2026, LLM-Assisted PRF (arXiv:2601.11238)](https://arxiv.org/abs/2601.11238) · **claim**: RM3-style PRF "remains vulnerable to topic drift when top-ranked documents are non-relevant — a particular weakness for short/vague queries"; i.e., PRF amplifies whatever the first pass returns, so it must sit on top of a fused first pass, not a failing BM25 alone. · **relevance**: RQ1/FR-001 · **confidence**: high
- **source**: [BEIR (Thakur et al. 2021, arXiv:2104.08663)](https://arxiv.org/abs/2104.08663) · **claim**: Dense retrievers tuned in-domain (MS MARCO) transfer poorly out-of-domain while BM25 stays robust — the canonical statement of the lexical/semantic complementarity that motivates keeping both paths. · **relevance**: RQ1+RQ2 · **confidence**: high
- **source**: [NQE: Neural Query Expansion for Code Search (FSE 2019)](https://dl.acm.org/doi/10.1145/3315508.3329975) · **claim**: Query expansion specifically for NL→code vocabulary mismatch gives significant gains over un-expanded queries — the expansion model is a small trained network (deterministic at inference, no generative LLM), so it is doctrine-compatible in spirit. · **relevance**: RQ1/FR-001 · **confidence**: high
- **source**: [Lemos et al., Thesaurus-Based Automatic Query Expansion for Code Search (MSR 2014)](https://otaviolemos.github.io/papers/msr2014-lemos.pdf) · **claim**: A thesaurus mined from API documentation bridges NL-word ↔ identifier vocabulary mismatch deterministically — the closest published analogue to "map query nouns to identifier tokens". · **relevance**: RQ1/FR-001 · **confidence**: medium
- **source**: [QECK (arXiv:1703.01443)](https://arxiv.org/pdf/1703.01443) · **claim**: Expansion terms sourced from crowd knowledge (Stack Overflow) improve code-search queries — evidence that *external* term sources help, though cairn's hermetic doctrine rules out the crowd source itself. · **relevance**: RQ1/FR-001 · **confidence**: medium
- **source**: [Hybrid search in production (tianpan.co)](https://tianpan.co/blog/2026-04-12-hybrid-search-production-bm25-dense-embeddings) · **claim**: Practitioner evidence that "pure dense retrieval fails silently on exact identifiers, code, and rare terms" — sentence queries with embedded identifier-like tokens need those tokens surfaced for the sparse path. · **relevance**: RQ1/FR-001 · **confidence**: medium (practitioner, not peer-reviewed)
- **source**: [Hybrid Search: BM25 and Dense (mbrenndoerfer.com)](https://mbrenndoerfer.com/writing/hybrid-search-bm25-dense-fusion) · **claim**: "BM25 consistently fails on semantic queries and dense consistently fails on lexical queries" — the two failure modes are systematic and complementary, so per-path rescue (identifier emphasis for BM25, noun-phrase for dense) is the standard remedy. · **relevance**: RQ1/FR-001 · **confidence**: medium

**Net for RQ1**: no-LLM expansion = (a) deterministic identifier/noun-phrase extraction with term weighting, (b) RM3/Bo1-style PRF over the *fused* first pass. PRF is the best-sourced lever; query2doc-style expansion without a generative model reduces to PRF (doc2query-style expansion requires a generator — out of doctrine).

## RQ2 — Hybrid fusion and thresholds

- **source**: [Cormack, Clarke, Buettcher, SIGIR 2009 (RRF origin)](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) · **claim**: RRF (Σ 1/(k+rank)) beat Condorcet and learned fusion; k=60 is the original recommendation. · **relevance**: RQ2/FR-003 · **confidence**: high
- **source**: [Bruch et al., An Analysis of Fusion Functions for Hybrid Retrieval (arXiv:2210.11934)](https://arxiv.org/abs/2210.11934) · **claim**: Contrary to received wisdom RRF *is* sensitive to its k parameter; a learned convex combination (one weight) outperforms RRF both in- and out-of-domain, is agnostic to score-normalization choice, and "needs only a small set of training examples to tune its only parameter to a target domain" — directly licenses cairn's tune-split weighting. · **relevance**: RQ2/FR-003 · **confidence**: high
- **source**: [Milvus RRF ranker docs](https://milvus.io/docs/rrf-ranker.md) + [RRF explained (blog.serghei.pl)](https://blog.serghei.pl/posts/reciprocal-rank-fusion-explained/) · **claim**: k=60 is the ecosystem default, but for *short* fused lists (top-10 style) k∈[1,10] gives the head more discriminative weight; k controls spiky-vs-flat rank contributions. · **relevance**: RQ2/FR-003 · **confidence**: medium
- **source**: [BGE-M3 paper (arXiv:2402.03216)](https://arxiv.org/html/2402.03216v3) + [EmergentMind BGE-M3 topic](https://www.emergentmind.com/topics/bge-m3-embedding-model-3ae9be85-46f0-4bec-be49-80d85554d4a6) · **claim**: bge-m3 embeddings are unit-normalized (dot = cosine); the paper fuses dense+sparse+ColBERT scores via self-knowledge-distillation rather than a fixed threshold. · **relevance**: RQ2/FR-003 · **confidence**: high
- **source**: [BGE-M3 threshold discussion (search-derived consensus)](https://www.emergentmind.com/topics/bge-m3-embedding-model-3ae9be85-46f0-4bec-be49-80d85554d4a6) + [Cosine-similarity unreliability thread](https://www.reddit.com/r/LanguageTechnology/comments/15egrkb/cosine_similarity_in_sentence_transformers_how_to/) · **claim**: No universal cosine cutoff exists for bge-family models; community practice puts "relevant" around ~0.6–0.7 for bge-m3 while unrelated pairs of many models still score 0.6+ ("I like cats" vs "I hate cats" ≈ 0.74) — absolute thresholds are unreliable and must be calibrated on own labeled pairs. · **relevance**: RQ2/FR-003 (is fixed 0.3 sane? → evidence says calibrate, folklore thresholds unsound) · **confidence**: medium (no official number; consistent direction across sources)
- **source**: [Calibrated Similarity (arXiv:2601.16907)](https://arxiv.org/html/2601.16907v1) · **claim**: Monotone calibration on labeled pairs restores interpretability of absolute cosine values — the principled alternative to a hand-picked threshold. · **relevance**: RQ2/FR-003 · **confidence**: medium
- **source**: [GoPenAI hybrid search analysis](https://blog.gopenai.com/hybrid-search-in-ragag-dense-sparse-bm25-splade-reciprocal-rank-fusion-and-when-to-use-which-fafe4fd6156e) · **claim**: BM25 hurts dense only when fused badly (score-scale mixing without normalization/RRF); rank-based fusion sidesteps scale mismatch entirely. · **relevance**: RQ2/FR-003 · **confidence**: medium

**Net for RQ2**: plain RRF k=60 is the defensible default; weighted RRF / one-parameter convex combination tuned on the split is *better-supported than expected* (Bruch et al.). Dense thresholds: no source sanctions a fixed 0.3 — calibrate on DS-v1 score distributions.

## RQ3 — Chunk composition for symbol embeddings

- **source**: [UniXcoder (Guo et al., ACL 2022 / arXiv:2203.03850)](https://aclanthology.org/2022.acl-long.499.pdf) + [README](https://github.com/microsoft/CodeBERT/blob/master/UniXcoder/README.md) · **claim**: On CodeSearchNet, the strongest function representation *concatenates the code embedding with the docstring embedding* (function names unavailable at test time) — the canonical published recipe that docstring + code jointly beat either alone. · **relevance**: RQ3/FR-002 · **confidence**: high
- **source**: [How Does Chunking Affect Retrieval-Augmented Code Search? (arXiv:2605.04763)](https://arxiv.org/html/2605.04763v1) · **claim**: 864-setting ablation (4 chunking strategies × 4 retrievers × 5 generators, RepoEval + CrossCodeEval): function-level chunking consistently underperforms declaration/sliding-window/cAST by 3.57–5.64pp (Cliff's δ = −1.0) and is never Pareto-optimal; surrounding context length matters more than chunk size. Caveat: measures downstream completion quality, not symbol recall — but it is the strongest 2026-vintage evidence that bare function/minimal chunks underdeliver. · **relevance**: RQ3/FR-002 · **confidence**: high (for its setting), medium (transfer to symbol recall)
- **source**: [Chunking strategies guide (dipakkr/ai-engineering-guide)](https://github.com/dipakkr/ai-engineering-guide/blob/main/03-retrieval-and-rag/05-chunking-strategies.md) · **claim**: Practitioner pattern of embedding signature and docstring (the NL-facing surfaces) rather than implementation — "the docstring embeds better for that query than the implementation does". · **relevance**: RQ3/FR-002 · **confidence**: low-medium
- **source**: [A Systematic Investigation of Document Chunking (arXiv:2603.06976)](https://arxiv.org/html/2603.06976) · **claim**: Across 36 chunking strategies, structure-aware and hierarchical chunking beat flat splitting — supports including structural metadata (qualified name/path) in the embedded text. · **relevance**: RQ3/FR-002 · **confidence**: medium (general-domain, not code-specific)
- **Gap**: no published ablation found that decomposes *name / qualified-name / path / signature / docstring* contribution for **symbol-level** retrieval specifically — that decomposition must come from cairn's own sweep (decide from first principles + measure).

## RQ4 — Reranker pair formatting

- **source**: [BAAI/bge-reranker-base model card](https://huggingface.co/BAAI/bge-reranker-base) · **claim**: Input is a (query, passage) pair; trained with cross-entropy so **raw relevance scores are unbounded** (not 0–1); max sequence 512 tokens. Directly implies cairn's confidence-gate threshold is a raw-logit-space number and *will* shift if pair text changes. · **relevance**: RQ4/FR-004 · **confidence**: high
- **source**: [Cloudflare bge-reranker-base docs](https://developers.cloudflare.com/workers-ai/models/bge-reranker-base) · **claim**: Sigmoid maps raw scores to [0,1] for normalized gating — the standard calibration move before thresholding. · **relevance**: RQ4/FR-004 · **confidence**: high
- **source**: [SentenceTransformers CrossEncoder docs](https://sbert.net/docs/package_reference/cross_encoder/model.html) · **claim**: `max_length`/truncation is an explicit constructor knob; pair truncation policy (which side loses tokens) is caller-controlled and matters at 512 tokens. · **relevance**: RQ4/FR-004 · **confidence**: high
- **source**: [CodeBERT/CodeSearchNet pair convention (via UniXcoder repo)](https://github.com/microsoft/CodeBERT/blob/master/UniXcoder/README.md) · **claim**: The established code-search rerank format is `tokenizer(query, code, truncation=True, max_length=512)` — query first, code second, single pair — with no published variant adding path/signature context to the candidate side. · **relevance**: RQ4/FR-004 · **confidence**: medium-high for the convention
- **Gap**: **no credible source found** for "does adding path/qualified-name/signature to the candidate side help bge-reranker?" — decide from first principles (measure on the sweep; the model card's unbounded-score property makes re-calibration mandatory either way).

## RQ5 — Small-ground-truth methodology

- **source**: [Smucker, Allan, Carterette, CIKM 2007](https://dl.acm.org/doi/10.1145/1321440.1321528) · **claim**: On TREC ad-hoc with **50 topics** (≈ cairn's 58 queries), randomization, bootstrap, and paired-t tests are practically interchangeable; Wilcoxon/sign tests should not be used. · **relevance**: RQ5/FR-006 · **confidence**: high
- **source**: [Urbano et al., Statistical Significance Testing in IR](https://julian-urbani.info/files/publications/076-statistical-significance-testing-information-retrieval-empirical-analysis-type-i-type-ii-type-iii-errors.pdf) · **claim**: Bootstrap is the most powerful test, t-test has lowest discordance — and agreement among tests *degrades as topic count shrinks*, so 58-query deltas need a significance guard, not just point estimates. · **relevance**: RQ5/FR-006 · **confidence**: high
- **source**: [Overtuning in Hyperparameter Optimization (arXiv:2506.19540)](https://arxiv.org/html/2506.19540v1) · **claim**: Repeated tuning against a fixed test set causes adaptive overfitting — the formal statement of the risk FR-006's tune/validate split guards against. · **relevance**: RQ5/FR-006 · **confidence**: medium-high
- **source**: [BEIR (arXiv:2104.08663)](https://arxiv.org/abs/2104.08663) + [Good Practices for ML Evaluation (arXiv:2412.03700)](https://arxiv.org/html/2412.03700v1) · **claim**: BEIR's guard is *zero-shot* evaluation (never tune on the eval set); several BEIR tasks have ~50 test queries and require significance testing before claiming wins — matching cairn's split-then-report-full-set discipline. · **relevance**: RQ5/FR-006 · **confidence**: high
- **source**: [Benham et al., Risk-Reward Trade-offs in Rank Fusion (ADCS 2017)](https://rodgerbenham.github.io/bc17-adcs.pdf) · **claim**: Fusion-parameter tuning itself exhibits risk/reward structure — small tuning sets can pick fusion parameters that win on the tuning set and lose in expectation; argues for conservative parameter grids on 58 queries. · **relevance**: RQ5/FR-003/FR-006 · **confidence**: medium
- **Gap**: no source prescribes a specific minimum query count or split ratio for retrieval parameter selection (50/50 vs k-fold); only the general small-sample overfitting literature — split design is a first-principles decision.

## Options summary (no recommendation)

**Choice 1 — query enrichment (FR-001)**: (a) deterministic identifier/noun-phrase extraction + BM25 term weighting — cheap, hermetic, practitioner-backed; (b) RM3 PRF over fused first pass — best-sourced gains, extra retrieval round (latency); (c) Bo1/Bo2 divergence PRF — alternative weighting, same cost; (d) API-doc thesaurus expansion — deterministic but needs a corpus to mine.

**Choice 2 — fusion (FR-003)**: (a) plain RRF k=60 — proven default, ignores tuned weights; (b) RRF with k∈[1,10] — sharper head weighting for short lists, less documented; (c) weighted RRF — middle ground, k still needs choice; (d) one-parameter convex combination (Bruch) — best evidence, requires score normalization + a tune split.

**Choice 3 — dense threshold (FR-003)**: (a) keep fixed 0.3 — no source support found; (b) calibrate fixed threshold on DS-v1 labeled score distribution — evidence-aligned; (c) monotone calibration to probabilities — principled, more machinery; (d) drop absolute threshold, use fused rank only — sidesteps the problem, may admit weak results.

**Choice 4 — chunk recipe (FR-002)**: (a) status quo name+docstring; (b) + qualified name + file path (structure-aware); (c) + signature (declaration-style, strongest in 2026 ablation); (d) UniXcoder-style docstring⊕code-text concat; (e) body prefix — risk of diluting NL surface. Must measure; no direct symbol-level ablation published.

**Choice 5 — rerank pair format (FR-004)**: (a) query vs current chunk; (b) query vs enriched chunk (name+path+signature+docstring) — unmeasured in literature, re-calibration mandatory; (c) truncation policy: candidate-side truncation vs query-priority — 512-token ceiling forces a choice.

**Choice 6 — split design (FR-006)**: (a) seeded 50/50 tune/validate; (b) k-fold CV (e.g., 5×~12) — better signal from 58 queries, more sweep compute; (c) 50/50 + paired significance test (bootstrap/t) as accept guard — Smucker/Urbano-aligned.
