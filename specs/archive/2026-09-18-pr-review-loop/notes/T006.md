# T006 spike notes — GitHub resolved-review-comment read path (FR-003)

Scratch: `tanlnm512/cairn-spike-t006` (private, PR 1, thread resolved in-session; deleted after the spike). Decision recorded via `cairn memory record decision` (memory/raw/2026-09-17-github-resolved-comment-read-path-gh-cli-gh-api-graphql-prim-76f593).

## Empirical results

| Read path | Resolution state? | Verified |
|-----------|-------------------|----------|
| REST `GET /repos/{o}/{r}/pulls/{n}/comments` | No `isResolved` field on the comment object (full JSON inspected) | curl + bearer token |
| REST `GET /repos/{o}/{r}/issues/{n}/events` | Empty — resolution emits no REST event | curl + bearer token |
| `gh pr view --json` | No review-thread/resolution field in the field list | gh CLI |
| GraphQL `repository.pullRequest.reviewThreads { isResolved ... }` | Yes — the only read path carrying it | `gh api graphql` and `curl POST /graphql` |

Resolution itself is also GraphQL-only (`resolveReviewThread` mutation); REST can neither read nor write it.

## Auth comparison

- **Token (curl + `Bearer $(gh auth token)` / `$GITHUB_TOKEN`)**: works for both REST and `POST /graphql`; caller manages secret hygiene and rotation; no external tool needed.
- **gh CLI (`gh api`, `gh api graphql`)**: keyring-managed token, built-in `--jq`, never shells to git (proven on this machine, where `/usr/local/bin/git` is x86_64-only and breaks git-invoking gh subcommands like `gh pr create`); gh is preinstalled on Actions runners and picks up `GITHUB_TOKEN` automatically.
- **cairn's own code needs neither**: `cairn review --capture-event` reads a JSON file; the network fetch belongs to the surrounding automation. Repo has no GitHub HTTP client (stdlib `urllib.request` only, embeddings), so a client dependency would trip C-03.

Decision: gh CLI primary, bearer-token curl fallback — recorded in memory.

## Payload shape T005's adapter must accept (one thread per file)

```json
{
  "resolved": true,
  "file": "src/ledger.py",
  "line": 4,
  "body": "stop parsing dates with regex — use a date library",
  "thread_url": "https://github.com/OWNER/REPO/pull/42#discussion_r4032719660"
}
```

Provenance (GraphQL thread node): `resolved`←`isResolved`, `file`←`path`, `line`←`line` (null ⇒ file-level keying, same degradation as TC-011), `body`←`comments.nodes[0].body` (carries the `cairn:pattern` marker D-003 classifies on), `thread_url`←`comments.nodes[0].url` (the `pull/42` link FR-003 requires in the memory body).

Producer (one command, verified):

```bash
gh api graphql -f query='query($o:String!,$n:String!,$num:Int!){repository(owner:$o,name:$n){pullRequest(number:$num){reviewThreads(first:100){nodes{isResolved path line comments(first:1){nodes{body url}}}}}}}' \
  -f o=OWNER -f n=REPO -F num=42 \
  --jq '.data.repository.pullRequest.reviewThreads.nodes[] | {resolved: .isResolved, file: .path, line: .line, body: .comments.nodes[0].body, thread_url: .comments.nodes[0].url}'
```

Webhook trigger alternative: `pull_request_review_thread`, action `resolved` (GitHub Docs, Webhook events and payloads).

Fixture mapping (TC-009/010/011): same five fields; `resolved-comment.json` `resolved:true`, `unresolved-comment.json` `resolved:false`, `orphan-line-comment.json` `file:"changelog.md"`.
