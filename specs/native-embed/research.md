### RQ3 — fastembed init cost and concurrency: is a lazy singleton + mutex sound; pre-warm API separation?

- **source**: https://docs.rs/fastembed/latest/fastembed/struct.TextEmbedding.html · 7.5.0, 2026-10-23 · **retrieved**: 2026-10-29 · **claim**: `TextEmbedding` implements auto traits `Send + Sync` (and `!Freeze`, `!RefUnwindSafe`, `!UnwindSafe`), while `embed` and `transform` take `&mut self` — so concurrent callers must serialize on shared state, `Send + Sync` makes a process-wide `static` + `Mutex<TextEmbedding>` (lazily initialized once, e.g. `OnceLock<Mutex<..>>`) compile-sound, and mutex serialization both satisfies the `&mut self` contract and prevents repeated model loads (NFR-004). · **relevance**: NFR-004, NFR-002 · **confidence**: high
- **source**: https://docs.rs/fastembed/latest/fastembed/struct.TextEmbedding.html (try_new docs) and https://docs.rs/fastembed/latest/fastembed/struct.BaseInitOptions.html · 2026-10-23 · **retrieved**: 2026-10-29 · **claim**: init cost is dominated by download-if-uncached plus session build — `try_new` "Uses the highest level of Graph optimization" and "Uses the total number of CPUs available as the number of intra-threads", with `with_intra_threads` to cap CPU and `with_session_config` for entries like `mlas.disable_kleidiai`; fastembed v7.3.2 (https://github.com/Anush008/fastembed-rs/releases, retrieved 2026-10-29) fixed "Share the default ORT environment", and `BaseInitOptions::with_environment(ort Environment)` lets callers share one ORT `Environment` across instances. · **relevance**: NFR-003, NFR-004, FR-006 · **confidence**: high
- **source**: https://docs.rs/fastembed/latest/fastembed/struct.TextEmbedding.html + https://docs.rs/fastembed/latest/fastembed/enum.OnnxSource.html + https://docs.rs/fastembed/latest/fastembed/ (crate index) · 2026-10-23 · **retrieved**: 2026-10-29 · **claim**: there is no dedicated public download-only API — the documented `TextEmbedding` surface is only `try_new`, `try_new_from_user_defined`, `get_model_info`/`get_default_pooling_method`/`get_quantization_mode`, `list_supported_models`, `embed`, `transform` (plus free fn `get_cache_dir`); download separates from inference in three evidenced ways: (a) pre-warm = call `try_new` and drop the instance (downloads populate the cache; later `try_new` calls "load from there"), (b) the pinned hf-hub 0.5 blocking `Api` (`Api::new().model("BAAI/bge-m3").get(file)`) downloads the catalog's four files without building a session, (c) `try_new_from_user_defined` with `OnnxSource::File(PathBuf)`/`Memory(Vec<u8>)` instantiates fully offline from local files. · **relevance**: FR-002 (`cairn embed --download-model` exits without embedding), FR-005 (no cache → hash fallback) · **confidence**: high

### Embedding crate choice
- fastembed 7.5.0 (ONNX via exactly-pinned `ort =2.0.0-rc.15`, hf-hub downloads) — closest to the old sentence-transformers flow, catalog already lists BAAI/bge-m3; heaviest tree (ort-sys build-time binary download, onig via tokenizers defaults)
- candle (pure Rust) — leanest build/license story, but bge-m3 is an XLM-R-large architecture: model code must be hand-rolled and weights/quality verified yourself
- raw `ort` + `tokenizers` hand-wiring — drops the fastembed wrapper layer, but reimplements pooling, normalization, and model-file mapping fastembed already ships

### bge-m3 surface (if fastembed)
- `TextEmbedding` + `EmbeddingModel::BGEM3` — dense 1024-dim vectors, exactly the `native/BAAI/bge-m3` contract
- `Bgem3Embedding` — dense+sparse+ColBERT in one pass; richer output than the dense-only stamp needs, at extra compute per embed

### Pre-warm mechanism (FR-002)
- `TextEmbedding::try_new(...)` then drop — one API, reuses fastembed's cache logic end to end; pays session-init cost inside the download command
- pinned hf-hub 0.5 `Api` download of the catalog files — download-only, no session; must mirror fastembed's file list (`onnx/model.onnx`, `onnx/model.onnx_data`, `onnx/Constant_7_attr__value`, tokenizer files) and cache-dir precedence

### Feature trim / TLS / ort backend
- fastembed default features vs `default-features = false` + `onnx` + `hf-hub-rustls-tls` (or `-native-tls`) — default drags in `image-models` (the `image` crate) and native-tls OpenSSL; trimmed build shrinks the cargo-deny surface and picks rustls vs system OpenSSL
- ort CPU backend via downloaded prebuilt binaries (default) vs `ort-load-dynamic` (dlopen a system ONNX Runtime) — vendor-the-binary shipping vs runtime-dependency and version-drift trade-off
