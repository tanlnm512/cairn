## Scenario construction

`search_memory` reads the OKF bundle at `~/.cairn/<workspace-key>/.knowledge`
(`review/engine.py` → `resolve_store(workspace).knowledge`); the workspace
`.knowledge/` tree and the graph DB's tables are not sources. A fresh runner
store starts memory-empty, and `review.yml` as authored never writes memories
into it, so the keyed-memory scenario needs the store seeded post-build. The
TC-012 branch's scratch copy of `review.yml` adds one setup step after
`Index workspace graph`, mirroring the guard fixture
(`tests/fixtures/review-loop/prepare.sh`: build, then `memory record` into
the same default store, default `--db`/`--knowledge`):

```yaml
      - name: Seed the keyed mistake memory
        run: |
          uv run --no-sync cairn memory record mistake \
            "Never resolve stores by walking" \
            --body "In the paths module, never resolve the store by walking the filesystem from resolve_store; use the registered workspace key." \
            --resource paths --confidence 0.8
```

The PR diff reworks `resolve_store` in `src/cairn/paths.py` (semantic no-op,
fixture `parse_date` pattern) so the seed symbol is `resolve_store`
(`paths` module). The review/base-ref/comment steps of `review.yml` are
untouched. A local sandbox dry run of the same flow printed the findings
markdown before any CI run.

## Defect for the T009 fix round: no memory-seeding path upstream

As authored, `review.yml` can never emit findings on the real repo:

- The CI store (`~/.cairn/<workspace-key>/`) is fresh per runner and the
  workflow never populates the knowledge bundle (no `memory record` step, no
  actions/cache, no `CAIRN_KNOWLEDGE` override pointing into the checkout).
- Committed files are never read as memories: the engine's bundle path is
  the store dir, not any repo tree.
- Verified: PR 3 (https://github.com/tanlnm512/cairn-spike-t010/pull/3)
  runs `review.yml` exactly as authored on `main` —
  https://github.com/tanlnm512/cairn-spike-t010/actions/runs/35183322540
  concludes `success` with an empty findings file. Silent-by-design
  (continue-on-error), so the gap never surfaces as a failure.
- Fix shape for T009 (pick one): commit a seed fixture and point
  `CAIRN_KNOWLEDGE` at it; or run `cairn memory record` in a documented
  seeding step; or actions/cache the store for repeat contributors.

## Non-findings

- `cairn build` creates the store parent itself; `cairn init` is NOT
  required before build on a fresh machine (PR 3's run built 532 files /
  8,516 symbols without it). An `Initialize the cairn store` step present on
  the TC-012/TC-013 branch copies is harmless but unnecessary.
- The macOS-built `_tree_sitter_kotlin.abi3.so` is gitignored; `setup.py`
  compiles the extension from the vendored binding at `uv sync` time —
  ubuntu CI parses the tree cleanly (184 skipped files, no parse failure).
