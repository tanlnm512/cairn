# T009 fix-round-1 notes — CI memory seeding for review.yml (FR-004, D-011)

Defect (T010 evidence): `review.yml` had no memory-seeding path —
`search_memory` reads the OKF bundle at the fresh per-runner store
(`review/engine.py` → `resolve_store(workspace).knowledge`); committed
files were never read as memories, so findings could never fire on a real
repo (silently green under `continue-on-error`; scratch PR 3 proved the
empty run).

## Fix (D-011 shape)

- `.github/workflows/review.yml`: job-level env
  `CAIRN_KNOWLEDGE: ${{ github.workspace }}/.cairn-knowledge` next to
  `CAIRN_EMBED_BACKEND`. Job level covers build + review + comment steps;
  verified the build step is safe with the env set (below). All other
  contracts untouched (advisory `continue-on-error`, no `--gate`, marker
  upsert, `fetch-depth: 0`, pinned `uv sync` install).
- Seed bundle `.cairn-knowledge/memory/tribal/` — 3 concepts generated via
  `cairn memory record` (CAIRN_EMBED_BACKEND=hash) against a repo graph, so
  the frontmatter replicates the real store's shape exactly
  (`Tribal-mistake`/`Tribal-pattern` type, `memory_signals` with
  `graph_verification: 1.0`, `memory_score: 0.6`, `memory_tier: tribal`,
  `valid_from`, `resource: <module>`, `okf_version: '0.2'`). Only the three
  concept files are committed — `log.md`/`.okf.lock` are runtime churn
  (`list_concepts` ignores `log.md`; the bundle works with concepts alone).

Seed keys (backticked body refs verified against the graph + `resource`):

- mistake "Run the repo CLI from the repo venv, never a global cairn
  install" — keys: `main`, `src/cairn`; resource `main` (pipx-stale-binary
  lesson).
- mistake "Shell git only with a working binary ahead on PATH" — keys:
  `_run_git`, `src/cairn/utils/git.py`; resource `git` (broken-x86-git PATH
  lesson).
- pattern "Seed the CI knowledge bundle or pre-submit findings never fire"
  — keys: `resolve_store`, `src/cairn/paths.py`, `build_pre_submit`;
  resource `paths` (this defect itself).

## Non-findings

- `.gitignore` ignores `.knowledge/` but not `.cairn-knowledge/` — no
  ignore change needed for the seed to ride the repo.
- Recording seeds against a graph-backed DB is what yields
  `graph_verification: 1.0` and the tribal tier; against an empty DB the
  same command stores under `memory/raw/` (still searchable, wrong shape
  for a committed seed).
