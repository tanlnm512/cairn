## RQ1 — PRF (RM3/Bo1) for short-query hybrid retrieval

- **source**: https://github.com/castorini/anserini (corroborated: https://trec.nist.gov/pubs/trec29/papers/KU.HM.pdf, https://dl.acm.org/doi/pdf/10.1145/3331184.3331340) · **claim**: Anserini's untuned RM3 default is fbDocs=10, fbTerms=10, originalQueryWeight=0.5, and untuned BM25+RM3 remains a strong baseline on Robust04. · **relevance**: RQ1 / FR-004 · **confidence**: high
- **source**: https://trec.nist.gov/pubs/trec29/papers/uogTr.DL.pdf (also https://pyterrier.readthedocs.io/en/latest/terrier/rewrite.html) · **claim**: Terrier's Bo1 (divergence-from-randomness) expansion ships with — and Glasgow's TREC 2020 run found very effective at — defaults of 3 feedback documents and 10 expansion terms, i.e. practical feedback depth is 3–10 docs, not 5–50. · **relevance**: RQ1 / FR-004 · **confidence**: high
- **source**: https://khui.github.io/files/publications/Hui2011_Chapter_AComparativeStudyOfPseudoRelev.pdf · **claim**: The governing PRF parameters are feedback-document-set size |ED| and expansion-term count |ET|, with RM3 adding the original-query interpolation weight λ (Q' = λ·Q_orig + (1−λ)·Q_exp). · **relevance**: RQ1 · **confidence**: high
- **source**: https://arxiv.org/abs/2305.07477 (SIGIR'23 version: https://scholarsmine.mst.edu/cgi/viewcontent.cgi?article=2733&context=comsci_facwork) · **claim**: Mackie et al. apply PRF and generative feedback across sparse, dense, learned-sparse, AND hybrid retrievers over six benchmarks — the direct precedent for running feedback off a fused first pass; generative feedback beat PRF by ~10% but PRF grounds expansion in the target corpus (relevant given our no-LLM doctrine rules the generative arm out). · **relevance**: RQ1 / FR-004 · **confidence**: med-high (hybrid internals from abstract + search summary; verify in full PDF before citing numbers)
- **source**: https://www.cs.cmu.edu/~callan/Papers/cikm21-HongChien-Yu.pdf · **claim**: ANCE-PRF (CIKM'21) re-encodes the query together with top-k first-pass passages to improve the dense query representation — the dense-leg analogue of PRF that stays deterministic and LLM-free (a bge-m3 re-encode is a candidate mechanism for our dense leg). · **relevance**: RQ1 / FR-004 · **confidence**: high
- **source**: https://dl.acm.org/doi/10.1145/3570724 · **claim**: More feedback is not better with strong retrievers — 15–20 feedback passages *hurt* effectiveness and contribute to query drift, so a shallow feedback depth (≤10) is the safe regime. · **relevance**: RQ1 failure modes / FR-004 · **confidence**: high
- **source**: https://dl.acm.org/doi/10.1145/3570724 + https://arxiv.org/abs/2601.11238 · **claim**: PRF failure mode on vocabulary-mismatched corpora is topic drift: expansion terms are drawn from a noisy top-k, so the same dominant (possibly wrong) vocabulary gets amplified — yes, PRF can amplify the same noise; mitigations are shallow depth, high λ, and expansion terms already IDF-flavored (Bo1 self-suppresses high-df terms). · **relevance**: RQ1 failure modes · **confidence**: med (synthesis of two sources)

## RQ2 — Multi-vector / late interaction at symbol granularity

- **source**: https://ar5iv.labs.arxiv.org/html/2112.01488 (corroborated: https://pages.di.unipi.it/rossano/assets/pdf/papers/ECIR24.pdf >140 GB; https://aclanthology.org/2022.acl-long.51.pdf ~112 GB) · **claim**: ColBERT's per-token late interaction costs roughly an order of magnitude more storage than single-vector retrieval (~154 GB for MS MARCO passages); ColBERTv2's residual compression cuts 6–10× with equal-or-better quality. · **relevance**: RQ2 / FR-005 · **confidence**: high
- **source**: https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00369/100684/ · **claim**: ME-BERT (Luan et al., TACL 2021) represents each document with a small fixed m vectors — one title vector + (m−1) body vectors — scored by (weighted) max over vectors, with the title found to carry disproportionate matching signal; this is the direct precedent for FR-005's name-only/docstring-only/chunk triple and lands storage at m× (≈3×) rather than per-token scale. · **relevance**: RQ2 / FR-005 · **confidence**: high
- **source**: https://huggingface.co/blog/lightonai/colgrep-lateon-code · **claim**: LateOn-Code / ColGrep apply ColBERT-style late interaction to code search — an existence proof of multi-vector code retrieval in production tooling. · **relevance**: RQ2 code-search precedent · **confidence**: med (vendor blog)
- **source**: https://arxiv.org/abs/2106.11251 · **claim**: Wang et al. (2021) study PRF over multiple-representation (multi-vector) dense retrieval — the RQ1×RQ2 crossover: expanding doc-side multi-vector representations is established. · **relevance**: RQ2 · **confidence**: med
- **source**: https://arxiv.org/html/2502.07067v1 and https://arxiv.org/html/2505.07849v2 · **claim**: Modern neural code search (repo-level retrieval, SweRank issue localization) is multi-stage dense/hybrid — no symbol-level multi-vector baseline found there, so FR-005's ablation row will be novel-ish evidence, not replication. · **relevance**: RQ2 · **confidence**: med

## RQ3 — Corpus-specific stopwording / IDF term weighting

- **source**: https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html · **claim**: The canonical industrial practice for df-based corpus-specific stopwording is a `max_df` threshold — terms with document frequency strictly above a proportion (typical 0.90–0.95) are dropped — which is exactly FR-003's "terms matching above a documented fraction of symbols" mechanism. · **relevance**: RQ3 / FR-003 · **confidence**: high
- **source**: https://arxiv.org/abs/2303.10439 · **claim**: Fan, Arora & Treude (NLBSE 2023) derived 200 domain-specific stopwords for software-engineering text from 10k Stack Overflow questions using information-theoretic (frequency/informativeness) methods, improving 17 of 19 downstream measures over a general stoplist — direct evidence that SE/code corpora need corpus-derived stopwording. · **relevance**: RQ3 / FR-003 · **confidence**: high
- **source**: https://www.issi-society.org/proceedings/issi_2015/0999.pdf · **claim**: Corpus-tailored stopword lists outperform universal lists for domain-specific collections. · **relevance**: RQ3 · **confidence**: med
- **source**: https://trec.nist.gov/pubs/trec29/papers/uogTr.DL.pdf (+ https://pyterrier.readthedocs.io/en/latest/terrier/rewrite.html) · **claim**: IDF-weighted query expansion is built into Bo1: expansion terms are scored by divergence between feedback-doc frequency and corpus-wide frequency, so ubiquitous tokens ("URL"-class) self-suppress — the RM3 route needs the same weighting added explicitly. · **relevance**: RQ3 × RQ1 · **confidence**: high
- **source**: none found (nearest practice: https://docs.weaviate.io/weaviate/concepts/search/keyword-search per-property BM25 boosting; https://github.com/sourcegraph/zoekt per-symbol-section score weights) · **claim**: No peer-reviewed source prescribes identifier-vs-prose term *weights* for code search — only field-boost practice in production engines exists — **decide from first principles + local ablation**. · **relevance**: RQ3 / FR-003 · **confidence**: low (absence of source)

## RQ4 — Ground-truth sizing for significance

- **source**: https://dl.acm.org/doi/10.1145/1321440.1321528 · **claim**: Smucker, Allan & Carterette (CIKM'07): the paired t-test, bootstrap, and permutation tests are essentially equivalent for IR evaluation while sign/Wilcoxon are weaker — the bootstrap guard is a first-class test, not a compromise. · **relevance**: RQ4 / FR-001 · **confidence**: high
- **source**: https://dl.acm.org/doi/10.1145/2911451.2911492 + Sakai, "Topic Set Size Design", Information Retrieval Journal 2016 (PDF: https://scispace.com/pdf/topic-set-size-design-3yru6wboa3.pdf) · **claim**: Topic-set-size design computes the required query count for target α/power from topic-by-run score matrices of past collections (Sakai ships Excel tools for paired-t designs) — the standard method to size DS-v2 rather than picking 3–5× by feel. · **relevance**: RQ4 / FR-002 · **confidence**: high
- **source**: https://arxiv.org/pdf/1905.11096 · **claim**: Urbano et al.'s ~500M-p-value empirical study quantifies Type I/II/III error rates as functions of topic-set size and effect size; small query sets systematically under-detect true effects — the predecessor spec's 58-query failure is the expected behavior, not an anomaly. · **relevance**: RQ4 / FR-002 · **confidence**: high
- **source**: https://sigir.org/files/forum/2014J/2014J_sigirforum_Article_TetsuyaSakai.pdf · **claim**: Sakai's statistical-reform position: always report effect sizes and CIs alongside p-values — matches the ablation-record style (Δ + CI + p). · **relevance**: RQ4 / FR-006 · **confidence**: high
- **source**: https://www.jmlr.org/papers/v5/grandvalet04a.html · **claim**: Bengio & Grandvalet (JMLR 2004): no unbiased estimator of k-fold CV variance exists from fold scores alone — per-fold spread must be reported as descriptive only, and significance must come from a test over pooled per-query paired errors, not fold means. · **relevance**: RQ4 / FR-001 (k-fold design) · **confidence**: high
- **source**: none (arithmetic) · **claim**: Bootstrap CI width shrinks ≈1/√n: the measured ±0.13–0.15 at n=29 implies ≈±0.07–0.08 at n≈120, which is why a +0.11 true effect clears at "n≈100+" — consistent with, and derivable from, the spec's own numbers. · **relevance**: RQ4 / FR-002 · **confidence**: med (standard CLT scaling, no single canonical URL)

## RQ5 — Cross-corpus evaluation design

- **source**: https://arxiv.org/abs/2104.08663 · **claim**: BEIR evaluates 10 retrievers across 18 datasets / 9 task types with models trained/tuned on MS MARCO and evaluated zero-shot on all others — tuning on one corpus and validating on others is the canonical accepted protocol, not a compromise. · **relevance**: RQ5 / FR-002 · **confidence**: high
- **source**: https://arxiv.org/abs/2104.08663 · **claim**: BEIR reports per-dataset metrics plus a macro-average (never an aggregate alone), and finds BM25 a robust out-of-domain baseline while dense models often underperform OOD — per-corpus rows are the anti-overfitting mechanism. · **relevance**: RQ5 / FR-002, FR-006 · **confidence**: high
- **source**: https://github.com/beir-cellar/beir · **claim**: Reference implementation of the per-corpus + macro-average reporting protocol. · **relevance**: RQ5 · **confidence**: high
- **Corollary for cairn**: the DS-v2 second corpus is the "validate on another corpus" leg; BEIR-style discipline = per-corpus ablation rows + macro-average, never diffing rows across corpora (matches the spec's existing risk note and D-010 immutability).

## Options summary (per open choice — no recommendation)

- PRF variant: RM3 (weighted interpolation, λ knob, 3 params) / Bo1 (DFR term scoring, no λ, self-IDF-weighted terms, 2 params) / dense-leg re-encode (ANCE-PRF-style; needs encoder fwd pass at query time, stays no-LLM).
- Feedback source: top-k of the fused list (Mackie precedent, single knob) / sparse-only top-k (traditional, ignores dense signal) / per-leg expansion then re-fuse (2 knobs, more drift surface).
- Feedback grid start point: docs 3–10 (Terrier 3, Anserini 10), terms ≈10, λ ≈0.5; deeper than 10 docs is the regime where drift is documented to hurt.
- Multi-vector shape: fixed m=3 doc vectors (ME-BERT precedent; ~3× storage) with max-score / weighted-max / plain weighted-sum scoring; per-token ColBERT-style ruled out on storage (~154 GB-class for one corpus).
- Stopword mechanism: hard df cutoff (max_df analogue at 0.90–0.95 corpus fraction; simple, deterministic) / soft IDF down-weight (term survives with low weight; smoother, one extra knob).
- GT sizing: Sakai-style power analysis from DS-v1 score matrices (defensible n) / fixed 3–5× scale-up (simpler, less defensible).
- k-fold aggregate: rotation-mean with per-fold spread reported descriptively + bootstrap over pooled per-query errors for the guard (Bengio–Grandvalet makes fold-score error bars invalid).
- Cross-corpus protocol: BEIR-style per-corpus rows + macro-average; tune-on-DS-v1 / validate-on-second-corpus (accepted practice).
