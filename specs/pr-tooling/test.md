# Test Cases: pr-tooling

**Spec**: [spec.md](spec.md) | **Created**: 2026-10-04
Black-box, business-language verification traced to requirements. Each case
has an observable pass condition. No implementation details.

Fixture contract (every pass condition embeds its own fixtures; each command
is self-contained, cleans up after itself, and finishes well under the 120 s
audit cap when run from the repo root):
- A throwaway workspace (`pkg/app.py` holding `mod_a` → `mod_b` → `mod_c`)
  under a temp dir, indexed by `cairn build` into a throwaway store passed
  via `--db` — no TC reads or writes this repository's own store.
- A fake `gh`: a temp bin dir prepended to PATH holding a stub that prints
  pinned fixture responses (PR-list JSON, PR-view JSON, unified diffs keyed
  by PR number) and logs its arguments when `CAIRN_STUB_LOG` is set. No TC
  reaches the network or a real gh.
- Community rows, where a case needs them, are seeded directly into the
  throwaway store's `communities`/`symbol_communities` tables (this spec
  consumes community tables, never builds them).

## TC-001 — PR list shows every field a reviewer triages by
