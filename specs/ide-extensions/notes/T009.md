## Iteration history (why the final design looks like this)
- spike.1: `xvfb-run -a code --extensionTestsPath <module>` "passed" in ~1s —
  false pass: the Linux `code` wrapper detaches window sessions, so the test
  module never ran. Caught by run 2's marker-file assertion.
- spike.2/3: marker file written from inside the exthost proved the wrapper
  detach; launching `/usr/share/code/code` directly boots the real session
  but the `--extensionTestsPath` bootstrap never completes on VS Code
  1.138.0 (session wedges after exthost start; run 3 hit the 15-min job
  timeout — cancelled).
- spike.4: bounded session + diagnostics on `always()` exposed the host's
  positive activation record in `exthost.log`.
- spike.5 (final): assert the host-recorded
  `ExtensionService#_doActivateExtension cairn.cairn` line directly (positive
  proof, no module/marker needed), bounded poll kills a wedged session.

## Honest limits
