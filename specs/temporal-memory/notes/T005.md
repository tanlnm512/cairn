- >=80% attribution: YAML parse of the 3 extra frontmatter keys per concept

- Predicate compute (`_valid_at`/`_bound_key`) does not appear in the top-45
  frames on either side. Memoized string compares are noise, as hypothesized.
- Node counts: compose_node calls 122000 (branch) vs 110000 (main) per query
  = 12000/2000 files = 6 extra nodes/file.

## Fix (in scope, write-side)

`write_validity` (src/cairn/memory/store.py) wrote all 3 keys unconditionally,
so still-valid memories carried 2 dead `null` lines that every read re-parsed.
Now a None bound pops its extensions key (absent == null == open interval to
every reader — all src readers use `.get()`; SQL row keeps explicit NULLs).
Files written by the fixed code carry only `valid_from` (2 nodes/file).

Post-fix node count: 114000 = main 110000 + 4000 (valid_from x 2000 files) —
the floor for FR-001's data-bearing key. Profiler-inflated per-query delta vs
main: +0.485s -> +0.310s (no-hit). The remaining delta is the irreducible
frontmatter growth of the feature's one required key across main's own
2000-reads-per-query architecture; removing it means caching parsed concepts
or SQL-side filtering (okf/graph layer, out of T005 scope).

Files touched: src/cairn/memory/store.py, tests/test_memory_validity.py (new
null-omission test + 2 assertions to .get form), tests/test_validate_paths_invalidation.py
(4 assertions), tests/test_schema_versioning.py (1 assertion).
